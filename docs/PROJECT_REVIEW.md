# Project comparison and ladder previews

These read-only operations use registered Logix snapshots. They preserve source files and managed revisions, require current hashes, and connect to no controller. ACD inputs must already have been registered through the separately configured SDK conversion path.

## Structural comparison

`POST /api/projects/compare` accepts:

```json
{
  "leftProjectId": "LEFT_ID",
  "leftSha256": "LEFT_CURRENT_SHA256",
  "rightProjectId": "RIGHT_ID",
  "rightSha256": "RIGHT_CURRENT_SHA256",
  "query": "MainRoutine",
  "offset": 0,
  "limit": 100,
  "includeRungNumbers": false
}
```

The `logix` extension exposes this as `studio_compare_projects`, with the body inside its `request` argument. Discover/describe it through the live catalog, then invoke it using `studio_extensions_read`.

Comparison reports additions, removals and modifications at component/metadata boundaries. Existing programs, AOIs and RLL routines are expanded; tags, UDTs, ST routines and unknown component XML are compared as whole units. A wholly added/removed subtree is one change, preventing duplicate parent/child counts. Declaration identities are matched case-insensitively; case-only attribute changes still appear. Renames are represented as removal plus addition.

XML attribute order, indentation between elements, root `ExportDate` and Controller `LastModifiedDate` are ignored. Scalar text, stored values, UDT member order, AOI parameter order, comments and unknown XML remain significant. Rung numbers are ignored by default and can be included explicitly. The report is structural, not a claim of native semantic equivalence.

Rung sequences use longest-common-subsequence alignment. A simple insertion does not mark all following renumbered rungs changed. Repeated identical rungs remain occurrences; moves are not inferred. Consecutive deletion/insertion runs are paired positionally into modifications, with remaining entries added/removed. Each entry includes source XPaths, normalized-content hashes and XML snippets capped at 4096 characters, with truncation flags. These hashes are comparison-unit hashes, not original-file hashes.

Counts cover all differences. `query` filters component paths/kinds before pagination, and `filteredChanges` reports that subset. Limits are 100000 XML elements and 64 levels per project, a 1000000-cell changed-rung alignment budget after common prefix/suffix removal, 200 rows per page, 256 query characters and a 4 MiB encoded response. Oversized unrelated sequences fail with `comparison_limit`; oversized pages use `comparison_page_too_large`. Stale snapshots use `stale_revision`.

## Ladder previews

`POST /api/projects/{id}/ladder-preview` accepts:

```json
{
  "expectedSha256": "CURRENT_SHA256",
  "routineXPath": "/RSLogix5000Content/Controller/Programs/Program[@Name='ExampleProgram']/Routines/Routine[@Name='MainRoutine']",
  "offset": 0,
  "limit": 5
}
```

The `logix` extension operation is `studio_ladder_preview`, with `projectId` and the body inside `request`. It uses the read dispatcher. Selectors must identify one RLL routine; obtain exact selectors from inspection rather than guessing names.

Each rung retains raw instruction text, comments and online-edit variant identity. Parsed rungs return instruction/operand nodes, wire coordinates and passive SVG generated by Core. Contacts/coils have familiar symbols; unknown instructions and AOIs use generic blocks. Instruction names and operand counts/types are not validated, and operands are not evaluated. There is no live power-flow display or simulation.

Supported structure includes instruction calls, nested operand parentheses, array indices, quoted operands, `[leg1,leg2]` branches and `BST/NXB/BND` branches. Malformed syntax returns an `invalid` row with diagnostics and no partial drawing. Limits produce `unsupported` rows; raw text remains available up to 65536 characters with a truncation flag. Comments are capped at 4096 characters with a separate flag. Full managed XML remains available through normal exports.

Limits: 20 rungs per page, 65536 characters per rung, 256 instructions/branches, branch depth 16, operand depth 32, diagram content dimensions 20000 pixels, 8192-character selectors and a 4 MiB encoded response. Use a smaller page after `ladder_page_too_large`. SVG labels are XML-encoded; output contains no scripts, external assets or executable markup.

## Community reference and validation

The review used [Logix Workbench revision 90b95236c71a2e37d44c11435468015f9126dcc5](https://github.com/ChrisMangin/logix-workbench/tree/90b95236c71a2e37d44c11435468015f9126dcc5), particularly its rung alignment and parallel-branch rendering approach. The C# comparison, bounded parser and layout are new implementations in the shared Core; no Rust/JavaScript source or runtime dependency was copied.

Generated tests exercise insertion/renumbering, same-count edits, repeated rungs, layout-sensitive order, quotes/arrays/nested branches, malformed syntax, SVG encoding, bounds, stale hashes and source preservation. These checks do not establish native Studio rendering, instruction semantics or controller behavior. See [VALIDATION.md](VALIDATION.md).
