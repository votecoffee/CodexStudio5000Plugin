# Native Studio Test / Untest / Assemble

This procedure requires the user-authorized controller/change. The user can operate Studio and report each resulting state; distinguish those reports from direct API measurements. When the user requests hands-off operation, use that handoff and do not control the UI. If UI automation is authorized instead, follow the installed Computer Use skill's initialization, current-window inspection and confirmation rules. The procedure's presence does not mean validation has occurred. Do not connect when the current request is local development only.

1. Identify the exact saved working ACD and controller path. After an SDK import, use the job's final ACD artifact saved as a new local file. Open it in Studio through supported UI interactions, confirm the controller identity and communications path, and reconnect only within the authorized scope. On correlation/upload/download prompts, inspect what Studio requires; do not choose a download or overwrite to make the dialog go away.
2. Inspect the program/routine and all pending/accepted/test edits in that program. The **Test Accepted Program Edits** command can switch every edited routine in that program. The active routine alone does not bound its effects. If unrelated edits exceed the user's scope, resolve that scope before testing; if program-wide testing is already authorized, proceed without another permission loop.
3. If edits remain pending, accept the intended scope before testing. With accepted edits, invoke **Logic → Online Edits → Test Accepted Program Edits** (labels vary by version) using current UI evidence. Read any listed affected routines and SFC/output implications. Handle the actual dialog under the existing user scope and the applicable UI confirmation rules. Observe the native Testing Edits state; a click or accepted dialog alone is insufficient evidence.
4. Check the user's specified behaviors and monitored values. Record the controller mode and distinguish observed logic execution from merely displaying Test Edits. A native test-state indicator does not establish a successful machine/process test. When conditions cannot be exercised or observed, report functional validation pending. If the test fails, use the authorized **Untest Accepted Program Edits** workflow, observe the restored state, and retain the failed-test result. Do not assemble a failed or unobserved functional test.
5. After the requested checks pass, assemble the tested scope. Prefer **Assemble Accepted Routine Edits** when supported and sufficient, or the expressly authorized program-wide assemble command. It requires Test Edits mode. Observe that the intended routine/program leaves Testing Edits and that edit zones resolve. Do not select **Finalize All Edits in Program** just to bypass missing test evidence or clear unrelated pending edits.
6. Save to the intended new working file, export a fresh result if needed, and retain its hash plus the observed native states and functional results. Registration/re-export through the service can verify saved content; it does not independently authenticate controller execution or UI provenance.

Do not use controller Test mode, `BuildAsync`, online tag writes or a second import as a substitute for Test/Untest commands. Do not introduce a download, mode change, force, safety unlock/signature deletion or unrelated edit cancellation to complete this workflow. Those are separate actions requiring their own actual user scope.

If a dialog shows unexpected scopes, communication is lost, the operation is indeterminate, or Computer Use is stopped, preserve the evidence and report the last observed state. Do not assume an automatic rollback, repeat the import, or continue assembling based on elapsed time.

- [Assemble Accepted Routine Edits](https://www.rockwellautomation.com/en-us/docs/studio-5000-logix-designer/38-01/contents-ditamap/studio-5000-logix-designer/navigating-the-application/-product_name_rsl5k--application-main-window/-product_name_rsl5k--application-commands/assemble-accepted-routine-edits-command.html): assembly replaces original logic and requires Test Edits mode.
- [Studio Logic menu](https://www.rockwellautomation.com/en-us/docs/studio-5000-logix-designer/38-01/contents-ditamap/studio-5000-logix-designer/logic-menu.html): distinct Test, Untest, Assemble and Finalize commands.
- Installed SDK 2.1.974 documentation, `LogixProject.PartialImportOption`: Leave leaves pending edits; Accept sends accepted changes; Finalize additionally assembles when the controller is in Run mode. These are import dispositions, not standalone edit-lifecycle commands.
