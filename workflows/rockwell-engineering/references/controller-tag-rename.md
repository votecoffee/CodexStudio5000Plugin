# Controller-tag rename

Discover `studio_controller_tag_rename_preview` (read) and `studio_controller_tag_rename_apply` (apply) using the live extension catalog and describe operation. This is an offline transformation of a managed Logix snapshot into a **separate** managed project, with a JSON receipt. It never edits the registered file or opens Studio/contacts a controller.

1. Supply `request` with `projectId`, `expectedSha256`, `tagName`, `newName`, `safetyHandling:"block"` and optional `decisions`. Only a controller-scope declaration is selected. New names must be valid nonreserved identifiers up to 40 characters; collisions and program-local capture block the change.
2. Inspect `references`, `findings`, `preservedRepresentations`, `canApply`, `reviewOnly`, `resultSha256` and `reviewSha256`. Each reference has an exact location, source-value hash and stable ID. Unqualified RLL/ST base identifiers and AliasFor references respect program-local shadowing. Explicit `Program:Name.Tag` references retain program scope. Routine/label/task symbol operands, quoted strings and source comments are retained. Members and dynamic index expressions are scanned separately. Unknown instruction/system-symbol operands require an exact decision: `{referenceId,choice:"rename"|"leave-symbol",reason}`. Preview again after changing decisions.
3. Safety declarations, changed safety-program references and simple `SafetyTagMap` pairs block by default. Use `safetyHandling:"review-only"` only for an explicitly authorized safety review copy. The output and receipt are marked review-only. Signatures and other safety configuration are preserved, without validating their continued applicability.
4. Apply with `{request:{preview:<the exact reviewed request>,expectedReviewSha256:<reviewSha256>}}` through the apply channel. The service recomputes the plan and exact source/review hashes; unresolved, stale or unsupported findings reject apply. Retain both `project` and `receipt`. Export the returned project and save the receipt with the normal artifact tools if needed.

Only selected raw identifier spans change. Encoding/BOM, all saved Data/ForceData representations, descriptions, comments, protected payload bytes and all unselected bytes stay unchanged. Split identifiers crossing XML CDATA/comment boundaries are unsupported. Limits include 1 MiB per executable/alias source, 16 MiB scanned source, 100,000 tokens, 10,000 references/findings, 1,000 exact decisions and an 8 MiB report.

This is lexical scope review, not a complete Logix compiler. Unsupported visible references outside supported fields block apply. AOI-local internals are separate scopes; protected code, external/HMI/remote references and native compiler/runtime bindings require independent review. Native import/build, safety acceptance and deployment remain separate authorized actions. Never replay an uncertain apply automatically; inspect retained projects/receipts first.
